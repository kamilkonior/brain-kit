# Learn: Return

The learning goes back to the work: the user is told in a few lines what was changed, where, and how to take it back, what was looked at and left as it is, what the work itself needs is handed to that work as an item, and the work is taken up where it stopped, under the changed way.

*Falls short:* a change the user cannot find, or work left dangling. *Overshoots:* a retrospective report nobody asked for, or staying on to rework what the lesson was about.

*Borders:* who decides what is changed belongs to agency; where the change lives belongs to mechanism; whether the user has pictured what will be different belongs to shared understanding; that the work is not repaired in passing belongs to containment, and return hands the repair over; naming the later sign belongs to proof, and return hands the look over; the design, the plan and the build themselves belong to the work returned to.

## Desirable

- **Change in a sentence:** the result is said first, in a sentence the user could pass on: what will be different from now on.
- **Changes listed:** each change is listed with its place (the file, the section, the check), what it says and how it is undone.
- **Unchanged said:** what was looked at and left (a thing judged a one-off, a change that did not pay) is named in a line each, with the reason.
- **Items for the work:** what the look showed to be wrong in the work itself (a step to repair, a decision to reopen) is written where that work keeps its record, as an item, and is done only on the user's word.
- **In force from when:** it is said whether the change already holds for the rest of this session or only from the next one on; where it holds, the work returned to is carried on by it.
- **The user's side repeated:** what the user said they would do differently is repeated in a line, as theirs.
- **Later look handed over:** where a sign was named or a look was set, it is written where it will be met (with the change itself, in the work's record), not left to memory.
- **Lesson for others:** where the lesson belongs to someone else (the author of a skill, the team, a tool's maker), what they need is drafted for the user to send.
- **Unfinished learning returned too:** a look that ends without a change hands back what was seen, what the likely cause is and what would settle it.
- **Workspace stated:** the user is told what the learning left: the changed files and nothing else, or what else, and where.
- **Back at the same place:** the design, the plan or the build the user came from is taken up where it stopped, and the user is told that this is where they are.
- **No record of its own:** the lesson lives in the change, and in the project's log of decisions where it keeps one; no file of lessons is made unless the user wants one.
- **Standalone wording:** what is written has no "as we saw" and no name coined in the session left undefined.
- **Closing word:** at the end the user knows what changed, where it is written, what is theirs to do and how to undo it.
- **Proportion:** the return from a lesson of one line is that line and its place.

## Undesirable

### Falls short

- **Change unfound:** something was saved, and the user does not know in which file.
- **Left dangling:** the learning ends, and the user has to work out where the interrupted build stood.
- **Old way resumed:** the work is taken up again, and its next step is done in the way that was just changed.
- **Fault left in the work:** the look showed that a step of the plan is wrong, and nothing was noted for the plan.
- **Unchanged unsaid:** three things were looked at and one was changed, and the user takes the other two for forgotten.
- **Look lost:** "let's see in a few weeks whether it helps" is said, and written nowhere.
- **No way back said:** the hook is in place, and the user does not know how to turn it off.

### Overshoots

- **Retrospective report:** a lesson of one line gets a document with a timeline, what went well and action items.
- **Lessons file:** a `LESSONS.md` is created in the repository, which nobody asked for and nothing reads.
- **Diary:** the course of the look, with every cause that was considered, is written into the work's record.
- **Staying on:** the session carries on into reworking the plan the lesson was about.
- **Action items for all:** tasks are handed out to the user and their team.
- **Told again:** the change is summarized, then listed, then summarized.

### Counterfeits (looks met, is not)

- **Story as result:** how the look went is told in place of what was changed.
- **"Updated the instructions":** this is the whole report, with no file, no text and no way back.
- **Promise in the report:** the closing lists what "will" be done differently, and half of it has no change behind it.
- **Item in the chat:** the repair the work needs is mentioned in the closing message, and written nowhere the work will look.
- **Looks standalone:** the sentences are complete, and "the earlier mix-up" resolves only with the session.
- **Filed and lost:** the change is written, and the user does not know where.
