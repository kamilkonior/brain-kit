# Spike: Proof

The answer is shown, not supposed: it is read off a run that could have come out the other way, held against the bar that was set before the run, a no is told apart from a spike that did not work, and the answer says how sure it is.

*Falls short:* "it works", after one run of the easy case. *Overshoots:* certainty pursued past what the decision needs.

*Borders:* the bar itself belongs to framing; whether the conditions of the run were those of the real thing belongs to realism; a slip in the code that spoils the result belongs to roughness; whether the result at hand is reason to stop belongs to limit; whose judgment counts in a question of taste belongs to agency; whether the user has the same picture of the result belongs to shared understanding.

## Desirable

- **Run and seen:** the spike was run, and the answer is what came out, not what the code should give.
- **Expectation first:** what is expected is said before the run, and a result that differs is treated as a finding.
- **Could have said no:** the run is one whose outcome was not fixed by the way the spike was made, and it can be said what a no would have looked like.
- **Held against the bar:** the result is held against what was set beforehand; where the bar is changed after the result, that is said, with the reason.
- **Measured where it is a measure:** a question of how fast or how much is answered with numbers, taken more than once, with their spread and with something to compare them to.
- **Tried to break:** after a yes, the case most likely to break it is tried, and what was tried is said.
- **No told from failure:** before "it cannot be done" or "it is too slow", the spike itself is suspected (a slip, a wrong use of what is being tried, a missing setting), and where a second way is at hand it is tried.
- **Exact no:** a no says what exactly was tried and what stood in the way, so that it is not read as more than it is.
- **Same for each rival:** in a comparison each way gets the same case, the same effort and the same care, also the one that you or the user favor.
- **Hoped-for result suspected:** a result that agrees with what you or the user hoped is checked as hard as one that does not.
- **Too good looked at:** a result that is better than it can be (no time at all, no errors in any row) is examined before it is believed.
- **Every part of the question:** each part of the question has its result, or is named as not answered.
- **The user's judgment taken down:** where the result is the user's judgment, they tried the spike themselves, and what they said is recorded as they said it.
- **Evidence shown:** the user sees the command and what came out, or runs it themselves, not a statement that it worked.
- **Can be run again:** while the answer may still be questioned, the command and the input that gave it are written down, and the run can be repeated.
- **Stated sureness:** the answer says whether it is shown, likely or a guess, on what that rests and what would change it.
- **Sureness follows stakes:** proof is heaviest where the decision is costly or hard to take back, and light where the first step of the build would show a wrong answer at once.

## Undesirable

### Falls short

- **One lucky run:** the spike ran once, on the easy case, and that is the yes.
- **Should work:** the code was written and read, and never run.
- **Felt, not measured:** "it feels fast" answers a question about speed.
- **Nothing to compare:** a number is reported, and nothing says whether it is good.
- **Failed spike as no:** "the library cannot do it" is reported, and the spike was using it wrongly.
- **Read to taste:** the result is read as a yes because a yes was hoped for.
- **Part for the whole:** one of the three things asked was tried, and the answer is given for all three.
- **Output unread:** the run went through without an error, and nobody looked at what it produced.

### Overshoots

- **Rig for a yes or no:** a benchmark harness is built where one timed run would decide.
- **Past the decision:** more runs are made after the user could already decide, and would decide the same.
- **Every case:** each input that can be thought of is tried, though none of them would change the answer.
- **No answer without certainty:** no likely answer is given because none is proven, though the user needs one in order to go on.
- **Hedged to nothing:** a result that was shown is reported with so many reservations that it says nothing.

### Counterfeits (looks met, is not)

- **Demo on rails:** the showing follows the one path that works, with fixed data, and is offered as the answer.
- **Bar moved:** "fast enough" is set after the number is known.
- **Rigged race:** the favored way is tuned, and its rival runs as it came out of the box.
- **Noise as difference:** two ways are run once each, and five percent between them names the winner.
- **Passed by the stand-in:** the result that was seen came from the part that was faked.
- **Expectation worded afterward:** "as expected" is said of a result nobody predicted.
- **Claimed run:** "I ran it and it works" is said, and no output shows it.
- **Boilerplate uncertainty:** "this should hold in most cases" is attached to the answer, with no word on what would settle it.
