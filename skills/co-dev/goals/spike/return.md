# Spike: Return

The answer goes back to the work that waited on it: it is written where that work keeps its record (the question, what was tried, what came out and how far it holds), it says what the answer means there, and the work is taken up where it stopped.

*Falls short:* an answer that stays in the conversation, or goes with the code. *Overshoots:* a report nobody asked for, or the real thing begun on the way out.

*Borders:* who decides what the answer means for the work belongs to agency; for what the answer holds belongs to realism, and how sure it is to proof; whether the user has the same picture of the result belongs to shared understanding; deleting the code belongs to disposal, and clearing away what the spike set up to containment; the design, the plan and the build themselves belong to the work returned to.

## Desirable

- **Answer in a sentence:** the question is answered first, in a sentence the user could pass on: yes, no, which, how much, or not found out.
- **Answer written:** the answer is written in a few lines: the question, what was tried, what came out (the numbers and the output that count), how sure it is, for what it holds and what was not tried.
- **Where the work keeps it:** it is written where the work that waited keeps its record (the design's open question, the plan's step or its list of assumptions, the issue), and where there is no such work, where the user says.
- **What it means there:** it says what the answer means for that work: a choice of the design settled or reopened, a step of the plan confirmed or to be changed, a risk that is new.
- **Decision handed back:** the decision that waited is put to the user with what is now known and your recommendation, and once made it is recorded in their sense.
- **Way that worked, in words:** the calls, their order, the versions and the settings that made it work are written exactly enough that the build does not have to find them again.
- **Traps handed over:** what cost time and will cost it again (the setting that is off by default, the error that misleads) is handed over in a line each.
- **A no recorded too:** what did not work is recorded with what was tried and what stood in the way, so that it is not tried again the same way.
- **New questions handed over:** what the spike raised and did not answer is listed, with what would settle each.
- **Workspace stated:** the user is told what the spike left: nothing, or what was kept, where and for how long.
- **Back at the same place:** the design, the plan or the build the user came from is taken up where it stopped, and the user is told that this is where they are.
- **Where it goes next:** where the user now wants the thing itself, it is said where that belongs: a design to change, a plan to make or a step to build.
- **Unfinished spike returned too:** a spike that ends without an answer hands back what was found, what stood in the way and what the next attempt would be.
- **Standalone wording:** what is written has no "as we saw" and no name coined in the spike left undefined, and can be read without the code.
- **Proportion:** the return from a spike of one call is its answer.

## Undesirable

### Falls short

- **Answer in the chat:** the result was said in the conversation and is written nowhere else.
- **Went with the code:** the numbers stood in the terminal, the code was deleted, and nothing was written down.
- **Bare "works":** the record says that it works, and not with what data, at what size or how far that holds.
- **Answer without consequence:** the result is reported, and nothing says what it means for the design or the plan.
- **Left dangling:** the spike ends, and the user has to work out where the interrupted work stood.
- **No lost:** the way that failed is recorded nowhere, and is tried again next month.
- **Traps lost:** the setting that took an hour to find is found again, the long way, in the build.
- **Workspace unknown:** the user does not know whether a scratch directory is still there.

### Overshoots

- **Report:** a spike of one call gets a document with headings.
- **Unasked documents:** a findings file is created in the repository that nobody asked for.
- **Spike diary:** every attempt and every dead end is written into the plan's record.
- **Begun on the way out:** "since it works", the package is added to the project and the first step is built.
- **Staying on:** the spike session carries on into designing or building the real thing.
- **Design rewritten:** the design is edited to fit the result before the user decided.

### Counterfeits (looks met, is not)

- **Story as answer:** the course of the spike is told in place of what it showed.
- **Code as record:** "see the scratch folder" stands in for writing down what was found.
- **Limits dropped:** the written answer says yes, and "on a sample, on this machine" stayed in the conversation.
- **Recorded as decided:** the record says that the library will be used, and the user never said so.
- **Looks standalone:** the sentences are complete, and "the second variant" resolves only with the session.
- **Filed and lost:** the answer is written down, and the user does not know where.
