# Spike: Disposal

The code goes when the answer is had: it is marked as a spike from its first line, its shortcuts are known, and at the end it is deleted, or kept by name outside the work on the user's word; what the work takes from the spike it takes as knowledge, and builds anew under its own rules.

*Falls short:* a spike that lives on, in the tree or as the beginning of the real thing. *Overshoots:* what the spike taught, thrown away with its code.

*Borders:* where the spike lives while it runs, and clearing away what it set up, belongs to containment; saying at the start that the code will go belongs to framing; who decides whether anything is kept belongs to agency; how rough the code may be belongs to roughness; writing down what the spike taught belongs to return; building the real thing belongs to the work returned to.

## Desirable

- **Marked:** each file of the spike says at its top what it is: a spike, for which question, not for use.
- **Said again at the showing:** when the spike is shown running, it is said again that this code will go.
- **Shortcuts known:** what the code leaves out or does wrongly on purpose (no errors handled, one user, fixed values, no tests) can be listed at any point, in a few lines.
- **Answer before deletion:** the code is deleted after the answer and what the spike taught have been written down and the user has seen them, not before.
- **Deleted:** at the end the spike's code is deleted, the variants that lost included, and the user is told that it is gone.
- **Kept while in doubt:** while the decision is open and the answer may be questioned, the spike is kept in its place so that it can be run again, with what will end the keeping.
- **Kept on the user's word:** where the user wants the spike kept (to show it to others, to run it again later), it is kept by name outside the work's sources, marked, with a line on how to run it.
- **Knowledge, not code:** what the real thing needs from the spike (the order of calls that works, the setting that mattered, the numbers) goes into the written answer, in words and at most a few quoted lines.
- **Carried over in the open:** where the user decides that a piece of the spike's code goes into the work, it goes in as a change of that work, under its rules, with its shortcuts repaired, and that is recorded.
- **Not the first version:** the work that follows starts from the design, the plan and what the spike showed, not from the spike's files.
- **Cost of keeping said:** when keeping the code comes up, what it lacks to be the real thing is listed from the known shortcuts, with what closing each would take.
- **Shown as a spike:** where the spike is shown to others, it is shown as a spike, with what in it is faked.
- **Proportion:** a line typed at a prompt needs no disposal.

## Undesirable

### Falls short

- **Lives on:** weeks later the spike is still in the tree, and nobody can say whether anything uses it.
- **Promoted:** the spike's directory is moved into the sources, and the work goes on from it.
- **Grown into the real thing:** the session keeps adding to the spike until it is the feature, and no build was ever begun.
- **"For now":** the code is kept "for now", with no word on until when or for what.
- **Pasted wholesale:** the first step of the build is the spike's file, copied in.
- **Unmarked:** the file stands among others under a name like any other, and nothing says it is a spike.
- **Shortcuts forgotten:** the code is kept, and nobody knows any more that it skips the check on access.
- **Shown as the product:** others see the spike, take it for the real thing and expect it next week.

### Overshoots

- **Deleted with the answer:** the code is removed before what it showed was written down, and the numbers go with it.
- **Deleted while in doubt:** the decision is still open, somebody asks to see the run again, and it cannot be shown.
- **Rule over sense:** twenty lines that are right are typed again from memory in order to keep the rule, and a mistake comes in.
- **Deleted over the user's head:** the user wanted to look at the code, or to keep it, and it is gone.
- **Knowledge refused:** the build is made to start as if the spike had never been run.

### Counterfeits (looks met, is not)

- **"Rewritten":** the spike is pasted into the sources with its names changed, and called built anew.
- **Moved, not removed:** the spike now lies in a `scratch/` folder of the repository, committed.
- **Commented out:** the spike stays in the sources as a comment.
- **"For reference":** the code is kept as a reference that nobody means to read.
- **Hardened in place:** tests and error handling are added to the spike, and that is called the build.
- **"Deleted":** this is said, and the spike's directory is still there.
